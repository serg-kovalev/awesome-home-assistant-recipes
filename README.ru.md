# Awesome Home Assistant Recipes

Практические рецепты для устройств, которые Home Assistant **не** поддерживает из коробки. Написано
по реальной работе с реальным железом — вместе с тупиками, в которые я заходил.

🇬🇧 [Read in English](README.md)

📖 Те же рецепты сайтом, с поиском: <https://serg-kovalev.github.io/awesome-home-assistant-recipes/>

## Зачем это

Облако производителя моего рекуператора отдаёт ровно **1** точку данных: вкл/выкл. В самом приборе
их **13** — 3 скорости, 3 режима проветривания, ночной режим, 3 порога влажности и 2
датчика. Всё, что умеет приложение, облачный API скрывает.

Производитель не сделал или не сумел. Пришлось сделать самому: полное локальное управление,
нормальная сущность `fan` со скоростями и пресетами, и голосовое управление через колонку.

Этот репозиторий — переиспользуемая часть той работы.

## Устройство, с которого всё началось

**Ventini HRV-60** — приточно-вытяжной рекуператор в сквозном монтаже, Tuya/SmartLife, Wi-Fi,
протокол 3.4. Категория в облаке `xfj`, product name «Heat Recovery Ventilator». Официальная
интеграция Tuya помечает его как **unsupported**.

Заодно разобран **Yandex YNDX-00535** — двухклавишный беспроводной Zigbee-выключатель, где главный
приём состоит в том, чтобы привязать его напрямую к реле, а не гонять каждое нажатие через
автоматизации.

## Про секреты

Все значения в репозитории — заглушки. Локальных ключей, ID устройств, идентификаторов облачного
аккаунта, MAC-адресов и настоящих сетевых диапазонов здесь **нет**, а файлы, которые их содержат
(`devices.json`, `tinytuya.json`, `snapshot.json`), перечислены в `.gitignore`.

Если будете повторять — помните, что Tuya `local_key` даёт полный контроль над устройством.
Относитесь к нему как к паролю: не вставляйте в issue, на форум и в скриншоты.
